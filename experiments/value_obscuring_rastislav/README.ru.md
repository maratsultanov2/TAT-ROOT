## Введение

**Value‑obscuring reversion** — это задача обнаружения попыток «тихого отката» в диалоговых системах. Пользователь хочет вернуть ранее изменённое значение, но **не называет ни само значение, ни явную команду отката** (например, «верни как было», «undo that change»). Стандартные методы (косинусное сходство, поиск по ключевым словам, сравнение значений) здесь практически слепы — F1 составляет 0.03–0.60.

**TAT (TreeAngleTap)** показал способность улавливать **структурный сигнал** — связь между высказыванием и историей изменений, а не поверхностные лексические совпадения.

Данные предоставлены независимым соавтором эксперимента — **Rastislav Drahos** (DanceNitra). Фикстуры построены так, чтобы последовательно исключать возможные «читы»: запоминание сущностей, ключевых слов, значений. Каждая следующая версия сложнее предыдущей.

## Методология

### Признаки

Для каждого примера (old → new → candidate) строится вектор признаков, отражающий **структуру диалога**, а не его семантику:

- **Theme** — идентификатор сущности (нормализованный хеш).
- **Role** — позиция высказывания в цепочке (0.0, 0.5, 1.0).
- **Emotion** — маркер намерения (1.0 — revert, 0.0 — keep, 0.5 — не определено), вычисляется по фиксированному словарю.
- **Meaning** — соотношение длин старого и нового значений.
- **Goal / Asserted Value** — какое значение утверждается кандидатом (старое, новое, или ни одно).
- **Cosine Similarity** (для v4) — косинусное сходство кандидата с контекстными строками old и new.

### Модель

**Triplenet** — архитектура с тремя параллельными путями (Yang, Yin, To) и константными паттернами, выделенными из обучающей выборки. Обучение — 100 эпох, CPU, время обучения менее 2 секунд.

### Протокол

Обучение проводится **только** на исходных данных (original fixture + first heldout). Тестовые выборки (v2, v3, v4) **не используются** ни для обучения, ни для построения признаков, ни для подбора порога. Порог фиксирован (0.5).

## Результаты

| Тест | F1 (TAT) | F1 (Baseline) | AUROC | Ключевая сложность |
|------|----------|---------------|-------|---------------------|
| v2 (новые фразы) | 1.0000 | 0.6000 (cosine) | 1.0000 | Парафраз без revert-слов |
| v3 (asserted value) | 1.0000 | N/A | 1.0000 | Только структурное утверждение значения |
| v4 (coreference, исправленный) | 0.6667 | N/A | 0.6362 | Кореференция без названного значения |

**Базилины для сравнения (v2):**
- Object/value match: F1 = 0.03
- Cosine similarity: F1 = 0.60
- Keyword rule (на основе revert/keep слов): F1 = 1.00 (v2), но падает до chance на v3 и v4

Только TAT сохраняет высокое качество на всех трёх уровнях сложности.

На исправленном v4 TAT достигает **recall 1.0** (все revert обнаружены), но precision = 0.5 из-за ложных срабатываний на keep. Проблема точно локализована: модель идеально определяет, есть ли в кандидате отсылка к роли из контекста (named_new 20/20), но не может связать эту роль с конкретным значением (старое или новое). Это второй шаг цепочки, и следующая цель для улучшения.
